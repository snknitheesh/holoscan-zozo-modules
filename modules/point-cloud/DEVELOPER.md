# holoscan-point-cloud developer guide

## Layout

```text
point-cloud/
├── CMakeLists.txt                 Standalone project against an installed Holoscan SDK 5.0
├── metadata.json                  Module metadata (urn:holoscan:module:v2)
├── cmake/                         Package config template; the CLI template's Debian helper
├── include/holoscan/point_cloud/  Installed public API
├── src/                           Operators, CUDA kernels; private headers
├── pkg/holoscan-point-cloud/      Debian packaging, entered when PKG_holoscan_point_cloud is ON
└── tests/
    └── installed_consumer/        Uses the installed package
```

The module follows the layout of the collection's other modules: public headers under `include/`,
one library for the public target, and the package config generated by the module itself, so that a
plain `cmake --install` produces a usable package. The Debian packaging keeps the CLI template's
`holohub_configure_deb()` and `PKG_holoscan_point_cloud` switch, so `holoscan package` works
unchanged. The folder is `point-cloud`, as the package is `holoscan-point-cloud`; C++ names cannot
hold a hyphen, so the headers, namespace and target say `point_cloud`.

## Build and package boundary

| | |
| --- | --- |
| Build contexts | Standalone top-level CMake project only; it is not built inside the SDK tree |
| Options | `BUILD_TESTING` (`OFF`), `PKG_holoscan_point_cloud` (`OFF`), `BUILD_SHARED_LIBS` (`ON`) |
| Public targets | `holoscan::point_cloud` (`libholoscan_point_cloud.so.1`) |
| Include root | `include/`, installed to `<prefix>/include` |
| Package | `<prefix>/lib/cmake/holoscan-point-cloud/holoscan-point-cloud-config.cmake`, `SameMajorVersion` |
| Consumer form | `find_package(holoscan-point-cloud)`; the install prefix on `CMAKE_PREFIX_PATH`, or `/usr` from the Debian package |
| Debian package | `holoscan-point-cloud`, all install rules, prefix `/usr`; depends on `holoscan (>= 5.0.0)` |
| External dependencies | Holoscan SDK 5.0 (`core`, `sensor_io`; `testing` for the tests), the CUDA runtime |
| Platforms | x86_64; aarch64 (Jetson Thor with JetPack 7, Jetson Orin with JetPack 7.2) |
| Test labels | `point_cloud` and `gpu` on all |

## Conventions

- Code lives in `holoscan::point_cloud`. The kernels' launchers and the synthetic depth camera are
  public and need no Holoscan graph; helpers shared by the operators stay private in `src/`.
- Public headers carry only SDK, CUDA runtime and standard types.
- Device code needs nothing newer than CUDA 13.0 (no CCCL header beyond its own), so the module
  also builds with JetPack 7's toolkit.
- Exact checks against the synthetic camera hold because nothing contracts floating-point
  arithmetic: `synthetic_depth.cu` is compiled with `--fmad=false`, and the library's and the tests'
  host code with `-ffp-contract=off`. Keep both for any code that renders or checks synthetic data.
- An operator has an optional port only when configured: an unconnected input is never satisfied,
  and an emit into an unconnected output fails.
- A new kernel option needs a case in `point_cloud_deproject`; a new port or behavior of the
  operator, a case in `point_cloud_depth_to_point_cloud_op`.
