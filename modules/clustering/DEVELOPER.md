# holoscan-clustering developer guide

## Layout

```text
clustering/
├── CMakeLists.txt                 Standalone project against an installed Holoscan SDK 5.0
├── metadata.json                  Module metadata (urn:holoscan:module:v2)
├── cmake/                         Package config template; the CLI template's Debian helper
├── include/holoscan/clustering/   Installed public API
├── src/                           Operators, CUDA kernels; private headers
├── pkg/holoscan-clustering/       Debian packaging, entered when PKG_holoscan_clustering is ON
└── tests/
    └── installed_consumer/        Uses the installed package
```

The module follows the layout of the collection's other modules: public headers under `include/`,
one library for the public target, and the package config generated by the module itself, so that a
plain `cmake --install` produces a usable package. The Debian packaging keeps the CLI template's
`holohub_configure_deb()` and `PKG_holoscan_clustering` switch, so `holoscan package` works
unchanged.

## Build and package boundary

| | |
| --- | --- |
| Build contexts | Top-level CMake project, or included by another project (`add_subdirectory()`, `FetchContent`, the repository root); it is not built inside the SDK tree |
| Options | Top level: `BUILD_TESTING` (`OFF`), `BUILD_SHARED_LIBS` (`ON`). Included: `HOLOSCAN_CLUSTERING_BUILD_TESTING` (`OFF`), always shared, the includer's `BUILD_TESTING` and `BUILD_SHARED_LIBS` left alone. Both: `PKG_holoscan_clustering` (`OFF`) |
| Public targets | `holoscan::clustering` (`libholoscan_clustering.so.1`) |
| Include root | `include/`, installed to `<prefix>/include` |
| Package | `<prefix>/lib/cmake/holoscan-clustering/holoscan-clustering-config.cmake`, `SameMajorVersion` |
| Consumer form | `find_package(holoscan-clustering)`; the install prefix on `CMAKE_PREFIX_PATH`, or `/usr` from the Debian package |
| Debian package | `holoscan-clustering`, all install rules, prefix `/usr`; depends on `holoscan (>= 5.0.0)` |
| External dependencies | Holoscan SDK 5.0 (`core`, `sensor_io`; `testing` for the tests), the CUDA runtime, CUB and libcu++ from the CUDA Toolkit (header-only) |
| Module dependencies | None: it reads holoscan-point-cloud's cloud layout, which is documented, without linking it |
| Platforms | x86_64; aarch64 (Jetson Thor with JetPack 7, Jetson Orin with JetPack 7.2) |
| Test labels | `clustering` and `gpu` on all |

## Conventions

- Code lives in `holoscan::clustering`. The clusterer (`clustering.hpp`), the drawing and the
  synthetic scene are public and need no Holoscan graph; the operator is thin: `CloudOp` receives,
  checks and stages the cloud and emits device tensors, and `EuclideanClusterOp` runs the clusterer
  in between. A new operator that takes a cloud derives from `CloudOp`. Helpers stay private in
  `src/`.
- Public headers carry only SDK, CUDA runtime and standard types; CUB and libcu++ stay in `src/`.
- Every result is deterministic. The union-find gives the same components whatever the order of its
  links, as a root is always its component's lowest node; sorts are stable; integer counts may use
  atomics, but floating-point sums are reduced in a fixed order (fixed chunks of the grouped
  points, a per-block tree, then the chunks in order). A new reduction must keep that.
- Exact checks hold because nothing contracts floating-point arithmetic: `clustering.cu` and
  `synthetic_scene.cu` are compiled with `--fmad=false`, and the library's and the tests' host code
  with `-ffp-contract=off`. A pair of points is linked by `squared_distance() <= tolerance^2`,
  computed as the CPU reference computes it; keep any new distance test in that form.
- `kEuclidean` relies on every two points of a cell being within the tolerance: cells are
  `tolerance / sqrt(3)` less a relative margin of 1e-5, which covers the rounding of the float
  distance. Points are assigned to cells in double. Do not widen the cells without testing pairs
  inside one cell.
- An operator has an optional port only when configured: an unconnected input is never satisfied,
  and an emit into an unconnected output fails. A refused emit cannot be retried, as the loan is
  gone; it fails the frame, with an error that names the port.
- A new clustering option needs a case in `clustering_clusterer` against the CPU reference or the
  truth; a new port or behavior of the operator, a case in `clustering_operator`.
