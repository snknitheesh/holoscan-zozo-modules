# holoscan-height-map developer guide

## Layout

```text
height-map/
├── CMakeLists.txt                  Standalone project against an installed Holoscan SDK 5.0
├── metadata.json                   Module metadata (urn:holoscan:module:v2)
├── cmake/                          Package config template; the CLI template's Debian helper
├── include/holoscan/height_map/    Installed public API
├── src/                            Operators, CUDA kernels; private headers
├── pkg/holoscan-height-map/        Debian packaging, entered when PKG_holoscan_height_map is ON
└── tests/
    └── installed_consumer/         Uses the installed package
```

The module follows the layout of the collection's other modules: public headers under `include/`,
one library for the public target, and the package config generated by the module itself, so that a
plain `cmake --install` produces a usable package. The Debian packaging keeps the CLI template's
`holohub_configure_deb()` and `PKG_holoscan_height_map` switch, so `holoscan package` works
unchanged. The folder is `height-map`, as the package is `holoscan-height-map`; C++ names cannot
hold a hyphen, so the headers, namespace and target say `height_map`.

## Build and package boundary

| | |
| --- | --- |
| Build contexts | Top-level CMake project, or included by another project (`add_subdirectory()`, `FetchContent`, the repository root); it is not built inside the SDK tree |
| Options | Top level: `BUILD_TESTING` (`OFF`), `BUILD_SHARED_LIBS` (`ON`). Included: `HOLOSCAN_HEIGHT_MAP_BUILD_TESTING` (`OFF`), always shared, the includer's `BUILD_TESTING` and `BUILD_SHARED_LIBS` left alone. Both: `PKG_holoscan_height_map` (`OFF`) |
| Public targets | `holoscan::height_map` (`libholoscan_height_map.so.1`) |
| Include root | `include/`, installed to `<prefix>/include` |
| Package | `<prefix>/lib/cmake/holoscan-height-map/holoscan-height-map-config.cmake`, `SameMajorVersion` |
| Consumer form | `find_package(holoscan-height-map)`; the install prefix on `CMAKE_PREFIX_PATH`, or `/usr` from the Debian package |
| Debian package | `holoscan-height-map`, all install rules, prefix `/usr`; depends on `holoscan (>= 5.0.0)` |
| External dependencies | Holoscan SDK 5.0 (`core`, `sensor_io`; `testing` for the tests), the CUDA runtime, CUB from the CUDA Toolkit (header-only) |
| Platforms | x86_64; aarch64 (Jetson Thor with JetPack 7, Jetson Orin with JetPack 7.2) |
| Test labels | `height_map` and `gpu` on all |

## Conventions

- Code lives in `holoscan::height_map`. The kernels (`height_mapper.hpp`, `traversability.hpp`,
  `views.hpp`) and the synthetic terrain are public and need no Holoscan graph; the operators are
  thin: `GridOp` gets the stream and allocates, commits and emits the layers, `map_info` and the
  images; each operator receives and checks its inputs and runs its kernels in between. Helpers
  shared by the kernels stay private in `src/`.
- Public headers carry only SDK, CUDA runtime and standard types; CUB stays in `src/`.
- The map's state lives on the GPU, structure of arrays, one buffer for all of it; the moving window
  copies it into a second buffer, shifted, and swaps them, so a cell is always at its row and column
  and the layers need no unrolling.
- Every result is deterministic: the points are binned by a stable radix sort, so each cell's
  points come in input order, and one thread sums them in that order; the image's automatic range
  uses integer atomics on ordered float bits, which commute. A new reduction must keep that.
- Exact checks hold because nothing contracts floating-point arithmetic: `height_mapper.cu`,
  `traversability.cu` and `synthetic_terrain.cu` are compiled with `--fmad=false`, and the
  library's and the tests' host code with `-ffp-contract=off`. The CPU references
  (`tests/reference.hpp`) follow the kernels' expressions in the same order, the pose's translation
  taken relative to the window's corner in double; a change to the kernels' arithmetic must change
  them too.
- An operator has an optional port only when configured: an unconnected input is never satisfied,
  and an emit into an unconnected output fails. A refused emit cannot be retried, as the loan is
  gone; it fails the frame, with an error that names the port.
- A new mapper or traversability option needs a case in `height_map_mapper` or
  `height_map_traversability` against a reference or the truth; a new port or behavior of an
  operator, a case in `height_map_operators`.
