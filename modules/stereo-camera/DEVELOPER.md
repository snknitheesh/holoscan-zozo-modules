# holoscan-stereo-camera developer guide

## Layout

```text
stereo-camera/
├── CMakeLists.txt                   Standalone project against an installed Holoscan SDK 5.0
├── metadata.json                    Module metadata (urn:holoscan:module:v2)
├── cmake/                           Package config template; the CLI template's Debian helper
├── include/holoscan/stereo_camera/  Installed public API
├── schemas/                         The calibration message's FlatBuffers schema
├── src/                             The operator, the backends, recordings; private headers
├── tools/                           stereo_camera_record, which also builds on its own
├── pkg/holoscan-stereo-camera/      Debian packaging, entered when PKG_holoscan_stereo_camera is ON
└── tests/
    ├── host/                        Tests that need no SDK, CUDA or GPU
    └── installed_consumer/          Uses the installed package
```

The module follows the layout of the collection's other modules: public headers under `include/`,
one library for the public target, and the package config generated by the module itself. The
folder is `stereo-camera`, as the package is `holoscan-stereo-camera`; C++ names cannot hold a
hyphen, so the headers, namespace and target say `stereo_camera`.

## Build and package boundary

| | |
| --- | --- |
| Build contexts | Top-level CMake project, or included by another project (`add_subdirectory()`, `FetchContent`, the repository root); `tools/` and `tests/host/` also build on their own, without the SDK |
| Options | Top level: `BUILD_TESTING` (`OFF`), `BUILD_SHARED_LIBS` (`ON`). Included: `HOLOSCAN_STEREO_CAMERA_BUILD_TESTING` (`OFF`), always shared, the includer's `BUILD_TESTING` and `BUILD_SHARED_LIBS` left alone. Both: `HOLOSCAN_STEREO_CAMERA_WITH_REALSENSE` (`ON`), `HOLOSCAN_STEREO_CAMERA_BUILD_RECORDER` (`ON` at the top level), `PKG_holoscan_stereo_camera` (`OFF`) |
| Public targets | `holoscan::stereo_camera` (`libholoscan_stereo_camera.so.1`) |
| Include root | `include/` and the generated message headers, installed to `<prefix>/include` |
| Package | `<prefix>/lib/cmake/holoscan-stereo-camera/holoscan-stereo-camera-config.cmake`, `SameMajorVersion`; sets `holoscan-stereo-camera_WITH_REALSENSE` |
| Consumer form | `find_package(holoscan-stereo-camera)`; the install prefix on `CMAKE_PREFIX_PATH`, or `/usr` from the Debian package |
| Debian package | `holoscan-stereo-camera`, all install rules, prefix `/usr`; depends on `holoscan (>= 5.0.0)`, and `librealsense2` when built with it |
| External dependencies | Holoscan SDK 5.0 (`core`, `sensor_io`; `testing` for the tests), the CUDA runtime; librealsense 2.50 or later, optional, linked privately |
| Platforms | x86_64; aarch64 (Jetson Thor with JetPack 7, Jetson Orin with JetPack 7.2) |
| Test labels | `stereo_camera`, and `gpu` or `host`; `data` on the real-data tests |

## Conventions

- Code lives in `holoscan::stereo_camera`. Only `stereo_camera_op.hpp` and
  `calibration_message.hpp` need the SDK; every other public header, and the backends, use the
  standard library alone (and librealsense, privately), so the recorder and the host tests build
  without the SDK. Keep it that way: the list of SDK-free sources is in `tools/CMakeLists.txt` and
  `tests/host/CMakeLists.txt` as well as here.
- A backend implements `StereoSource` in its own `src/*_source.cpp`, with its factory declared in
  `src/sources.hpp` and its checks in `validate(const SourceConfig&)`. It opens its device in
  `open()`, never in its constructor, and its frame views stay valid until the next `grab()`.
- A live backend gives only its newest frame, and the frame's age when it knows it; the operator
  turns that into the capture time.
- The realsense backend is compiled only with librealsense (`HOLOSCAN_STEREO_CAMERA_WITH_REALSENSE`
  is 0 or 1 in the sources); a build without it still names the backend and refuses it with a
  reason. The CI image has no librealsense, so CI does not compile it: build it with librealsense
  installed before changing `src/realsense_source.cpp`.
- The recording format and the calibration file are versioned (`kCalibrationFormatVersion`). A
  reader ignores keys it does not know; a change that old readers would misread needs a new
  version. The message schema only appends fields with new ids.
- An operator has an optional port only when the source gives that stream: an unconnected input is
  never satisfied, and an emit into an unconnected output fails.
- A new option, file rule or check needs a case in the host tests; a new port or behavior of the
  operator, a case in `stereo_camera_op`.
