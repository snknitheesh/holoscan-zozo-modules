# holoscan-pcl-filters developer guide

## Layout

```text
pcl-filters/
├── CMakeLists.txt                 Standalone project against an installed Holoscan SDK 5.0
├── metadata.json                  Module metadata (urn:holoscan:module:v2)
├── cmake/                         Package config template; the CLI template's Debian helper
├── include/holoscan/pcl_filters/  Installed public API
├── src/                           Operators, CUDA kernels; private headers
├── pkg/holoscan-pcl-filters/      Debian packaging, entered when PKG_holoscan_pcl_filters is ON
└── tests/
    └── installed_consumer/        Uses the installed package
```

The module follows the layout of the collection's other modules: public headers under `include/`,
one library for the public target, and the package config generated by the module itself, so that a
plain `cmake --install` produces a usable package. The Debian packaging keeps the CLI template's
`holohub_configure_deb()` and `PKG_holoscan_pcl_filters` switch, so `holoscan package` works
unchanged. The folder is `pcl-filters`, as the package is `holoscan-pcl-filters`; C++ names cannot
hold a hyphen, so the headers, namespace and target say `pcl_filters`.

## Build and package boundary

| | |
| --- | --- |
| Build contexts | Top-level CMake project, or included by another project (`add_subdirectory()`, `FetchContent`, the repository root); it is not built inside the SDK tree |
| Options | Top level: `BUILD_TESTING` (`OFF`), `BUILD_SHARED_LIBS` (`ON`). Included: `HOLOSCAN_PCL_FILTERS_BUILD_TESTING` (`OFF`), always shared, the includer's `BUILD_TESTING` and `BUILD_SHARED_LIBS` left alone. Both: `PKG_holoscan_pcl_filters` (`OFF`) |
| Public targets | `holoscan::pcl_filters` (`libholoscan_pcl_filters.so.1`) |
| Include root | `include/`, installed to `<prefix>/include` |
| Package | `<prefix>/lib/cmake/holoscan-pcl-filters/holoscan-pcl-filters-config.cmake`, `SameMajorVersion` |
| Consumer form | `find_package(holoscan-pcl-filters)`; the install prefix on `CMAKE_PREFIX_PATH`, or `/usr` from the Debian package |
| Debian package | `holoscan-pcl-filters`, all install rules, prefix `/usr`; depends on `holoscan (>= 5.0.0)` and `holoscan-messages (>= 1.0.0)` |
| Module dependencies | holoscan-messages (`module.dependencies`): `holoscan::messages` from the same build when the repository root added it, otherwise its installed package; the package config finds it for consumers |
| External dependencies | Holoscan SDK 5.0 (`core`, `sensor_io`; `testing` for the tests), the CUDA runtime, CUB (header-only, BSD-3-Clause) from the CCCL found first on the include path: the SDK's, then the CUDA Toolkit's |
| Platforms | x86_64; aarch64 (Jetson Thor and Jetson Orin, with JetPack 7.2) |
| Test labels | `pcl_filters` and `gpu` on all |

## Conventions

- Code lives in `holoscan::pcl_filters`. The filters (`filters.hpp`) and the synthetic scene are
  public and need no Holoscan graph; the operators are thin: `CloudFilterOp` receives, checks and
  stages the `PointCloud` message and sends the result in its layout with every field the input
  has, and each operator runs one filter in between. A kernel that writes a cloud writes every field
  `CloudOutput` has, in one launch: `CloudFilterOp` opens the writes of all the output's fields
  before it and commits them after.
  Helpers shared by the filters stay private in `src/`.
- Public headers carry only SDK, CUDA runtime and standard types; CUB stays in `src/`.
- Every result is deterministic: integer counts may use atomics, but floating-point sums are reduced
  in a fixed order (per-block trees over a fixed grid, then the blocks in order), sorts are stable,
  and RANSAC draws from a seeded sequence. A new reduction must keep that.
- Exact checks hold because nothing contracts floating-point arithmetic: `crop_box.cu`,
  `voxel_grid.cu`, `outliers.cu` and `synthetic_scene.cu` are compiled with `--fmad=false`, and the
  library's and the tests' host code with `-ffp-contract=off`. Keep both for any code that is
  checked against a CPU reference. `ground.cu` is checked against the truth with a tolerance and
  keeps fused multiply-adds for its scoring; its height cut uses `__fmul_rn` and `__fadd_rn`, so it
  decides as the host does.
- An operator has an optional port only when configured: an unconnected input is never satisfied,
  and an emit into an unconnected output fails. A refused emit cannot be retried, as the loan is
  gone; compute() returns its error, naming the port, which fails the run. A stop's
  `RUNTIME_PUBLICATION_STOPPED` error goes back unchanged, so that the run still ends stopped.
- No host wait per frame unless the output's size needs it (`kDense`) or the producer may reuse
  host input once compute() returns: count the waits a change adds (`cudaStreamSynchronize`, a
  synchronous copy) and say why in the README's cost table.
- A new filter option needs a case in `pcl_filters_filters` against a reference or the truth; a new
  port or behavior of an operator, a case in `pcl_filters_operators`.
